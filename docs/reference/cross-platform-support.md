# Cross-platform support

Oia targets macOS and Windows. Every rule below is a trap this repository has
already hit (or verified in code review) — not folklore. Read this BEFORE
touching process spawning, file paths, the codex CLI bridge, or the Electron
shell.

## Process spawning & the codex CLI

- **Never spawn the codex CLI directly.** Go through `CliRuntime`
  (`packages/providers/src/cli/runtime.ts`): it owns timeout ⇒ process-tree
  termination (POSIX: `detached` process groups; Windows: `taskkill /T /F` on
  the root PID). A bare `spawn()` leaks children that outlive the app — and a
  leaked codex child keeps burning ChatGPT quota invisibly.
- **Prompt text travels via stdin — never argv** (visible in `ps`, argv length
  limits, quoting bugs). `CliRunOptions.stdin` exists for this.
- **A detached child does NOT die with its parent.** Anything that owns detached
  children needs a shutdown handler that signals the children FIRST, then dies,
  with a bounded wait (see the main process `before-quit` and the utility
  SIGTERM trap — bug-reproductions #3).
- **npm `.cmd` shims cannot be spawned bare on Windows.** Resolution order for
  codex lives in `provision.ts`: `codex.cmd` / `codex.exe` / `codex.bat`, then
  the managed install (`<userData>/codex/current/bin/codex.exe`). Never
  `spawn("codex")` and hope.
- **Windows paths parse in three shapes.** `parseImagePathHint`
  (`providers/src/codex/bridge.ts`) accepts POSIX `/…`, `C:\…`, and `C:/…`. A
  single-style regex silently falls through to the "newest file" mtime scan,
  which attaches the WRONG image when jobs overlap (the B4 bug).

## PATH and GUI launches

- **An app launched from Finder/Dock/Start Menu does not inherit the shell
  PATH.** Codex installed via nvm/Homebrew/npm-user-dir will not be found by a
  naive `PATH` lookup. The runtime panel's managed install exists precisely to
  escape this: a pinned binary under `userData` beats PATH guessing.
- **Detect ≠ status.** `detect()` is side-effect-free (finds binaries);
  `status()` probes (version/login) and is cached + in-flight-deduped. Don't
  call `status()` on hot paths; don't use `detect()` when you need login state.

## Files

- **Use `path.join` — never assume `/` or `\`**, including in regexes that
  parse paths from CLI output (see above).
- **Renames fail transiently on Windows.** Antivirus and indexers hold files
  mid-rename (`EPERM`/`EBUSY`/`EACCES`). All persisted state goes through
  `atomicWriteJson` (`packages/tasks/src/atomic.ts`): temp + rename with retry
  and a single-writer promise chain per file. A plain `writeFile` to a state
  file is a bug regardless of platform.
- **Case-insensitive filesystems (macOS/Windows)**: file keys generated by the
  store are lower-case hex/uuid — keep it that way; a mixed-case key scheme
  will collide on rename.

## Electron shell

- **The preload MUST be `.cjs`.** `package.json` is `type: "module"` — a `.js`
  preload loads as ESM and *silently fails* under `sandbox: true`. Pinned in
  `electron.vite.config.ts` (cjs output) and named `index.cjs`.
- **Utility-process messaging**: this Electron line has no `UtilityProcess.port`
  — use `child.postMessage()` and `child.on("message", msg => …)` (the message
  arrives directly, NOT wrapped in `.data`; the child side's `process.parentPort`
  DOES wrap in `.data`). One of these days an upgrade will change this — pin the
  Electron version consciously.
- **`oia://files` needs CORS privileges.** Scene images load with
  `crossOrigin="anonymous"`; without `registerSchemesAsPrivileged({ corsEnabled:
  true })` + an `access-control-allow-origin` header, fabric `loadFromJSON`
  rejects and the canvas renders empty. file:// cannot reach the LocalFileStore
  at all — that's why the protocol exists.
- **Window hardening stays**: `contextIsolation: true`, `sandbox: true`,
  `nodeIntegration: false`, `will-navigate` prevented, `setWindowOpenHandler`
  deny. If a change needs one of these loosened, that's a design decision, not
  a workaround.
- **The loopback agent API's security gates are ordered on purpose** (Host
  literal ⇒ Origin reject ⇒ header-only key ⇒ body cap) and fire BEFORE any
  route logic. Read `docs/designs/desktop-only-reorg.md` § Loopback API spec
  before adding a route. Any new route inherits all gates.

## Platform checks

- Prefer `process.platform === "win32"` / `"darwin"` at the boundary (one
  place), not scattered through business logic. The `native/`-per-OS split
  (Orca-style) is step-7 work if platform code grows.
